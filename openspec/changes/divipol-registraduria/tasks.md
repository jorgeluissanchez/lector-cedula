# Tasks

Reglas para todas las tareas: TDD (principio II): cada prueba nueva se ejecuta y se ve fallar (rojo) antes de escribir el código que la satisface, y la salida en rojo se adjunta como evidencia en el PR. Datos sintéticos o públicos únicamente: los códigos y nombres de lugar no son datos personales, y los payloads de ejemplo siguen la skill `fixture-sintetico`. Código con barras invertidas, `Ñ` o escapes `\u` se escribe con la herramienta de escritura de archivos, no con heredoc, y se comprueban los bytes después (errores pasados de `CLAUDE.md`). Toda prueba que lance procesos declara `{ timeout: 60_000 }` en su `describe`. Tabla por requisito y comandos (`V`, `VC`, `G`, `I`, `M`, `R`, `L`, `P`, `E`, `C`) en `design.md`, sección `## Pruebas`. Tipos de prueba:

- **Unitaria**: un `it` por escenario, nombrado `"<ID> <escenario>"`, con los literales de la spec y `toStrictEqual`.
- **Propiedad**: fast-check, `numRuns >= 1000`, generadores válidos por construcción; o recorrido exhaustivo sin filtro.
- **Fuzz de entrada**: `fc.anything()`, `fc.string()` y `fc.string({ unit: "binary" })`, 0 excepciones.
- **Integridad**: conteos, checksums y tablas literales de la spec sobre los archivos versionados (oráculo independiente del generador).
- **Integración**: `spawnSync` de la CLI sobre directorios temporales.
- **Mutación**: `npm run test:mutacion` con >= 85 % en cada archivo mutado.
- **Licencias / privacidad**: `npm run check:licencias` y `npm run check:privacidad`.
