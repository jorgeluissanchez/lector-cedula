# Tasks

Todas las tareas siguen TDD (principio II): primero la prueba con los valores literales de la spec, verla fallar, luego implementar. Nombre de cada prueba: `"<ID> <escenario>"`. Datos sintéticos únicamente (skill `fixture-sintetico`); todo archivo de prueba que contenga `PubDSK_1` lleva `// fixture-sintetico` en la primera línea. Comandos abreviados como en design.md (sección Pruebas): `V` = `npx vitest run packages/fixtures`, `T` = `npm run typecheck`, `L` = `npx eslint packages/fixtures`. Las propiedades usan `numRuns >= 1000` y, si tienen ramas, contadores con umbral (design.md, decisión 9). Ninguna aserción usa el cálculo de dígitos ni el codificador del generador como oráculo (decisión 11).
