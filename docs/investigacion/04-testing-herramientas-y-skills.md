# Testing: herramientas y skills para que ninguna spec improvise pruebas (2026-10-06, segunda pasada verificada)

**Pregunta.** Qué skills/agentes de Claude Code y qué herramientas concretas por tipo de prueba debe exigir toda spec del lector de cédula, con licencia, comando e instalación.

**Respuesta corta.** Base ya instalada y suficiente para el 80 %: Vitest 3.2.7 + fast-check + Stryker + Playwright 1.63 (con cámara falsa) + @axe-core/playwright + superpowers. Faltan: Vitest browser mode (`@vitest/browser@3.2.7`, sin subir de versión), Schemathesis y Hypothesis (Docker) para la API, gitleaks/osv-scanner/Semgrep/ZAP/Trivy en Docker con versión fijada, onnxruntime-node 1.30 para golden tests de modelos, y augraphy (MIT) para distorsiones de documentos. Playwright 1.63 ya trae `init-agents` e `init-skills` (no hace falta instalar `@playwright/cli` global). Los Playwright Test Agents chocan con `specs/` de Spec Kit: configurar sus planes en `e2e/planes/`. Trivy sufrió un compromiso de cadena de suministro en marzo de 2026: usar >= 0.75.0 fijado por digest.

**Leyenda.** [V] verificado en fuente primaria: código instalado en `node_modules`, caché del plugin, archivos del repo, o en la web (registro npm/PyPI/Docker Hub/GHCR/MCR vía API, repositorio y archivo LICENSE vía API de GitHub, documentación oficial) el 2026-10-06, con URL. [E] estimado o no confirmable en fuente primaria: **verificar con `licencia-check` antes de instalar**.

### Receta: cámara simulada en Playwright [V parcial]

1. Generar el vídeo sintético con el generador de `fixture-sintetico` y convertirlo: `docker run --rm -v "$(pwd -W):/w" -w /w jrottenberg/ffmpeg:8-alpine -loop 1 -i cedula.png -t 5 -r 15 -pix_fmt yuv420p e2e/videos/cedula.y4m` (tag `8-alpine` existe en Docker Hub [V]; parámetros de ffmpeg [E]) (Y4M 4:2:0; MJPEG también válido; el archivo se repite en bucle).
2. Proyecto Playwright aparte: `launchOptions.args: ['--use-fake-ui-for-media-stream', '--use-fake-device-for-media-stream', '--use-file-for-fake-video-capture=e2e/videos/cedula.y4m']` (ya están los dos primeros [V]).
3. Para WebKit/Firefox o para variar imágenes por prueba: `page.addInitScript` que reemplace `navigator.mediaDevices.getUserMedia` por `canvas.captureStream()` dibujando la imagen sintética.
4. Asertar con espera por condición (`expect.poll` / `waitForFunction`), nunca `waitForTimeout` (skill `condition-based-waiting`).

### Pruebas metamórficas de visión [E]

Relaciones obligatorias sobre imágenes sintéticas: rotación ±3°, perspectiva leve, blur gaussiano sigma <= 1, glare fuera de la zona del código, brillo ±20 %, JPEG calidad 70 -> **la salida decodificada no cambia**; y en sentido contrario, distorsión fuerte -> el score de calidad baja y el frame se rechaza (nunca un número distinto). Implementables en Vitest con canvas/OpenCV.js y onnxruntime-node.

## Impacto en la spec

- Toda spec (Spec Kit y OpenSpec) debe incluir una sección **"Pruebas"** que, por cada requisito, nombre: tipo de prueba, herramienta, comando y umbral de la matriz C. `spec-writer` la rellena; `verificador` rechaza si falta o si el comando no se ejecutó.
- Hook `SubagentStop`: exigir además mutation score de Stryker en archivos tocados de `packages/parsers` (modo `--incremental`).
- Regla nueva: ninguna imagen Docker de seguridad ni acción de CI se referencia por tag mutable (`latest`, `stable`, `vX`); siempre versión exacta y, en CI, digest o SHA (lección del incidente Trivy).
- La migración a Vitest 5 queda fuera de las specs de producto: es una spec de infraestructura propia.

## Decisión recomendada

Adoptar la matriz C como estándar; crear la skill de proyecto `estrategia-pruebas` redactada desde cero; añadir solo lo que falta, en este orden y previa pasada de `licencia-check`: `@vitest/browser@3.2.7`, `onnxruntime-node@1.30.0`, `npx playwright init-agents --loop=claude --prompts`, `npx playwright init-skills`, `/plugin install property-based-testing@trailofbits`; e imágenes Docker fijadas: `ghcr.io/schemathesis/schemathesis:4.29.4`, `semgrep/semgrep:1.179.0`, `zaproxy/zap-stable:2.17.0` (o `ghcr.io/zaproxy/zaproxy:stable`), `ghcr.io/google/osv-scanner:v2.6.0`, `aquasec/trivy:0.75.0`, `zricethezav/gitleaks:v8.30.1`, `ghcr.io/data-privacy-stack/presidio-analyzer:2.2.364`, `locustio/locust:2.46.7`. No adoptar AlbumentationsX, imgaug, Deepchecks, pa11y ni `@playwright/cli` global.

## Cambios de la segunda pasada (2026-10-06)

Verificación con API de npm/PyPI/Docker Hub/GHCR/MCR, API de GitHub (estado, archivado, licencia SPDX, LICENSE) y documentación oficial. Cambios relevantes:

1. **Vitest**: la versión vigente ya no es 4 sino **5.0.3** (2026-09-30). Para browser mode no hace falta subir: con 3.2.7 se usa `@vitest/browser@3.2.7` + `provider: 'playwright'`. `@vitest/browser-playwright` solo existe desde 4.0 y exige la misma versión exacta de vitest.
2. **Playwright 1.63** trae `init-skills` (skills `playwright-cli`, `playwright-component-testing`, `playwright-trace`) y `npx playwright cli`; el `@playwright/cli` global es redundante. `--prompts` existe en el código pero no en la doc; la doc confirma que no hay opción para cambiar `specs/`. Corregido el comando del MCP (`claude mcp add playwright npx @playwright/mcp@latest`).
3. **trailofbits/skills**: licencia CC BY-SA 4.0 confirmada; marketplace `trailofbits`; existen `property-based-testing`, `static-analysis`, `testing-handbook-skills`, `semgrep-rule-creator`, etc. Su `mutation-testing` solo cubre mewt/muton. Advertencia de ShareAlike si se copia su texto.
4. **Semgrep MCP** (`semgrep/mcp`) está archivado; el servidor vive ahora dentro del binario `semgrep`. Licencia de reglas: Semgrep Rules License v1.0 (solo uso interno).
5. **Jazzer.js** no está archivado: 4.0.0 salió el 2026-04-15 (Apache-2.0), pero sigue integrado solo con Jest. Se mantiene fast-check como fuzzer principal.
6. **Albumentations** original archivado (2025-07-10, MIT); **AlbumentationsX** confirmado AGPL-3.0-only/comercial. **imgaug** no archivado pero sin release desde 2020. **augraphy** MIT confirmado (última release 2023-12).
7. **Carga**: k6 AGPL-3.0 confirmado; **Artillery es MPL-2.0, no MIT**; autocannon MIT sin release desde 2024-10; se recomienda Locust (MIT, imagen oficial) como alternativa limpia.
8. **Trivy**: incidente de cadena de suministro confirmado (GHSA-69fq-xp46-6x23, marzo 2026) que afectó al binario 0.69.4, a todas las tags de `trivy-action`/`setup-trivy` y a las imágenes Docker Hub 0.69.5/0.69.6. Usar 0.75.0 por digest.
9. **Schemathesis**: imagen principal `ghcr.io/schemathesis/schemathesis` (también en Docker Hub); en Windows usar `host.docker.internal` en lugar de `--network host`; añadido `-w auto` y versión fijada.
10. **gitleaks**: subcomando `detect -s` sustituido por `git`/`dir`; proyecto "feature complete" y sucesor Betterleaks (MIT) en v2 RC.
11. **Presidio**: transferido de Microsoft a `data-privacy-stack`; la imagen correcta es `ghcr.io/data-privacy-stack/presidio-analyzer` (MCR ya no se actualiza).
12. **Cámara del emulador Android**: la opción documentada es `-camera-back imagefile:<archivo>` / `videofile:<archivo>` / `environment`; `virtualscene` no figura en la doc actual.
